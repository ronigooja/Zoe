## Native interface coverage

The client interface is being redesigned. For each supported form factor (macOS, regular/narrow iPad, and iPhone), capture current native screenshots and exercise empty/loading states, pending submission, send failure, task progress, results, waiting decisions, failed/canceled tasks, and safe stop. Cover light/dark appearance, English/Chinese localization, Dynamic Type, VoiceOver, keyboard/focus behavior, window resizing, and draft preservation/reconciliation. A rendered HTML reference, syntax pass, or build does not establish those outcomes.

Real-device voice acceptance records device/OS, 30-minute mixed Mandarin–English locked-device sessions on both iPhone and iPad, automatic startup attempts, route changes, interruptions, reconnects, permission denial, lifecycle/policy interruptions, account/server unavailability, truthful status, text fallback, turn/command identities, impact-level authorization, task continuity, and confirmed capture/playback termination. Measure actual outcomes without retaining raw audio. Account/media safe reuse and trusted transport remain open. Ordinary results must not display Accept/Reject workflow; high-impact actions must reject ambiguous text and accept only scoped explicit confirmation.

## Quality evidence

For every dimension in [product chapter 20](../product.md#20-overall-quality-requirements), record the tested environment, procedure, threshold where approved, observed measurement, evidence, and gap. Numeric targets not yet approved remain unresolved; no dimension is accepted from a design claim. Production restore targets require measured RPO/RTO and separately measured index rebuild time.

## Authentication and recovery gates

Use the current instance-key model for fresh deployments: credential denial, rotation, stale deployment-key failure, Keychain-only storage, QR/link import, HTTP confirmation, local clearing, and installation-isolated push registrations. Local clearing must not stop durable tasks or revoke another installation. Historical authentication procedures are not current acceptance conditions.

[Chat recovery](evidence.md#chat-recovery-correction) is source-reviewed, remote-unverified. Acceptance requires a live authorized continuation/recovery chain with actual runtime, provider, artifact, stop, and capacity evidence. Do not infer old uncertain runs recovered from a source correction or healthy service.
