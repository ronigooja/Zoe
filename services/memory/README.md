# Zoe memory worker

The authority and derived-store boundary is defined by [ADR 0006](../../docs/architecture/decisions/0006-memory-authority-and-derived-stores.md). This document records the memory worker's implementation parameters; see [deployment operations](../../docs/operations/deployment.md#server-and-worker-settings) and [data lifecycle](../../docs/operations/data-lifecycle.md) for operational procedures.

Dependency versions are locked in [pyproject.toml](pyproject.toml) and [uv.lock](uv.lock). [config.py](config.py) pins the multilingual embedding revision, dimension, and codec; [embedding.py](embedding.py) checks model artifacts. A codec change requires a new collection rebuilt from Go authority. [Compose](docker-compose.yml) uses disposable Qdrant tmpfs and persists Mem0 history, ownership metadata, and model cache in `memory-worker-state` at `/var/lib/zoe/memory`; include that volume in the applicable backup/deletion inventory.

The opt-in cross-language harness lives in [e2e_worker.py](tests/e2e_worker.py) and [Go integration tests](../../tests/integration/). Supply `ZOE_MEMORY_E2E=1`, `ZOE_MEMORY_E2E_LLM_BASE_URL`, `ZOE_MEMORY_E2E_LLM_MODEL`, and `ZOE_MEMORY_E2E_LLM_API_KEY` through deployment references to run `go test ./tests/integration -run '^TestMemoryWorkerGoPythonMem0QdrantEndToEnd$' -count=1`. It uses synthetic sources, a temporary authority database, and disposable Qdrant; a Responses stub exercises composition only.

For background jobs, each Responses API request reserves a call and an input estimate equal to the UTF-8 request bytes plus framing allowance, together with its requested output-token ceiling, in the Go authority before dispatch. The default per-job limits are four physical calls and 192,000 reserved units. Reservations count across retries; an uncertain or crashed call remains reserved. Provider usage is recorded when returned and stays explicitly unknown when absent. Later budget checks count the greater of a call's reservation or measured usage. The estimate is not provider usage or a tokenizer-specific guarantee; accounting does not set monetary cost. SDK retries are disabled so one reservation authorizes one physical request. `ollama` is rejected until its calls can use the same accounting path.

Cleanup removes Mem0 history only when the worker can prove claim ownership from the durable ownership map or surviving vector metadata. Pre-ledger history without such an owner remains untouched; the Mem0 history schema has no safe claim mapping for those rows.

## Internal person memory API

When `ZOE_MEMORY_API_TOKEN_FILE` is set, the worker reads its bearer token and starts a standard-library HTTP listener at `ZOE_MEMORY_API_ADDR` (default `0.0.0.0:8788`). Otherwise it logs one disabled message. All routes, including `GET /healthz`, require bearer authentication. POST JSON bodies are limited to 64 KiB except `/v1/memory/ingest`, which allows 256 KiB (including JSON framing, measured in bytes); `ZOE_MEMORY_API_TIMEOUT_SECONDS` bounds responses (default 60, maximum 120). In-flight backend operations cannot be forcibly interrupted; mutation outcomes after timeouts are uncertain, so callers must not blindly retry writes or ingestion. Concurrency is bounded and new mutations check the deadline before dispatch.

For person-scoped requests, the caller supplies an opaque `user` encoding workspace plus owner subject, never claim identity. The worker hashes it into a separate `zoe-person-` namespace. `POST /v1/memory/search` accepts `{user,query,top_k?}` (default 8, maximum 20), uses no LLM, and returns `{items:[{id,text,score}]}`. `POST /v1/memory/write` accepts `{user,sentence,restatement}`, recalls five memories, makes one configured LLM call, validates all operations before applying them, and returns `{operations:[{op,id?,text}]}`. Replacement references are exact memory text, not model-visible IDs or aliases; unmatched or ambiguous references become adds. `POST /v1/memory/delete-all` accepts `{user}` and removes vectors plus history/messages scoped through a durable ID-only person ownership ledger. Unknown pre-ledger history cannot be attributed safely and is not globally purged.

For transcript ingestion, `POST /v1/memory/ingest` accepts exactly `{user,text}` with nonempty, non-whitespace string fields. The `text` is conversation transcript data, including completed tasks as original requests and results, not instructions. Invalid input returns HTTP 400 `{error_kind:"request_invalid"}` before Mem0 is called. The handler makes one Mem0 `add(text, user_id=person_user_id(user), infer=True, prompt=INGEST_INSTRUCTIONS)` call; Mem0 extracts durable self-stated user facts/preferences, excluding assistant statements and task content except durable outcomes stated by the user. [INGEST_INSTRUCTIONS](person_memory.py) defines these categories without examples or behavioral requirements. The response is HTTP 200 `{added:int,updated:int}`, counting `ADD` and `UPDATE` result events; empty extraction returns zeros. Ingestion shares write's person ownership/history tracking, deletion scope, serialization, and deadline handling.

For synchronous writes and ingestion, no job headers or job-scoped ledger are used: one request makes one extraction LLM call. Only the HTTP write and ingest handlers enter the explicit `unaccounted_sync_call()` context; the adapter still refuses every call lacking job accounting outside that context. Background extraction/indexing keeps mandatory reserve/finalize accounting and its budget gate, as described above. SDK retries remain disabled on both paths.

When `ZOE_LOG_LEVEL=debug` (default `info`), Zoe logs search query/results, complete write model input/output, ingest text/instructions and Mem0 results, and permits Mem0 content logs. At INFO, each synchronous LLM call logs only `memory_api llm_call component=<memory_write|memory_ingest> status=<ok|error> error_kind=<none|backend_unavailable|deadline_exceeded> elapsed_ms=<duration>`; requests log fixed request-kind labels (`ingest` for ingestion), status, and duration. Neither INFO record includes content, user IDs, credentials, or raw exception messages. HTTP client debug logging remains disabled to protect credentials. Legacy claim extraction/indexing remains unchanged.
